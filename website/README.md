# Transformer LoL Report — Companion Website

Stakeholder-facing report site for the IEEE ICT-PEP 2026 paper
*"Transformer Loss-of-Life Acceleration under High Rooftop-PV Penetration on
Indonesian 150/20 kV Substations."* All seven paper figures rebuilt as
interactive Plotly charts driven directly by the CSVs in `../results/tables/`.

## Stack

- Next.js 14 (App Router) + TypeScript + Tailwind CSS
- `react-plotly.js` + `plotly.js-dist-min` (CDN-free, dynamic-imported on the client)
- KaTeX for the small number of equations on the methodology page
- Static export — `npm run build` produces `out/` that drops onto any web host

Fonts: **Geist** (UI), **Newsreader** (editorial display), **JetBrains Mono** (numerics).
Inter is intentionally not used. Design system follows the `design-taste-frontend`
and `impeccable` skills installed at `~/.claude/skills/`.

## Running locally

Prerequisites: Node.js 20+.

```bash
cd transformer_lol_sim/website
npm install
npm run dev
# → http://localhost:3000
```

`npm run dev` automatically runs the CSV→JSON data pipeline (`predev` script).

## Static export

```bash
npm run build       # writes ./out
npx serve out       # local check
```

The `out/` directory is self-contained — copy it onto a static host (Vercel,
GitHub Pages, NGINX, Caddy, an internal PLN file share) and it works.

## Data pipeline

`scripts/build_data.mjs` reads the CSVs and JSON in `../results/` and writes
compact JSON to `public/data/`. It runs automatically before `dev` and `build`;
to regenerate manually:

```bash
npm run data
```

| Source | Output | Drives |
|---|---|---|
| `results/metrics.json` | `public/data/metrics.json` | Stat callouts, runtime chart |
| `results/tables/table1_scenario_definitions.csv` | `public/data/scenarios.json` | Scenario catalogue |
| `results/tables/table2_lol_statistics.csv` | `public/data/lol_stats.json` | Fig. 3, 6, 7 + explorer |
| `results/tables/table3_surrogate_performance.csv` | `public/data/surrogate_metrics.json` | Fallback for Fig. 2 |
| `results/tables/dispatch_comparison.csv` | `public/data/dispatch.json` | Fig. 4 box plots |
| `results/tables/surrogate_holdout.csv`† | `public/data/surrogate_holdout.json` | Fig. 2 scatter / CDF |

† Generated by `python scripts/06_export_holdout_predictions.py` (one-time export).
If absent, Fig. 2 falls back to a summary metric panel rather than the scatter.

## Updating the report after a new paper run

1. Re-run scripts 01–05 in `transformer_lol_sim/scripts/` to regenerate
   `results/metrics.json` and the CSVs in `results/tables/`.
2. (Optional) re-run `python scripts/06_export_holdout_predictions.py` to
   refresh the Fig. 2 scatter data.
3. Update `content/findings.ts` so the headline copy and pull-quote numbers
   match the new metrics — every number on the site should reconcile to
   `results/metrics.json` and `results/tables/table2_lol_statistics.csv`.
4. `npm run build` and redeploy `out/`.

If a headline number in the site disagrees with `metrics.json`, treat that as
a release blocker — the paper is authoritative.
